# Система ролей бота

Бот использует систему ролей для управления доступом к командам.

## Роли

1. **Owner (Владелец)** 👑
   - Высший уровень доступа
   - Может управлять администраторами
   - Имеет доступ ко всем командам

2. **Admin (Администратор)** 🔧
   - Может управлять настройками бота
   - Не может управлять другими администраторами
   - Имеет доступ к большинству команд

3. **User (Пользователь)** 👤
   - Базовый уровень доступа
   - Может использовать информационные команды
   - Не может изменять настройки

## Распределение команд

### Для всех пользователей (User, Admin, Owner)
- `/help` - показать список команд
- `/get_prompt` - показать текущий системный промпт
- `/status` - текущее состояние бота
- `/metrics` - показать счётчики
- `/send_test <текст>` - отправить тест к DeepSeek
- `/holiday_check` - проверить праздники на сегодня

### Для администраторов (Admin, Owner)
- `/set_prompt <текст>` - изменить системный промпт
- `/reset_prompt` - сбросить промпт к значению по умолчанию
- `/set_history_limit <число>` - установить лимит хранимых сообщений
- `/set_autopost_interval <сек>` - интервал автосообщений
- `/enable_autopost` - включить автосообщения
- `/disable_autopost` - выключить автосообщения
- `/enable_reactions` - включить автоматические реакции
- `/disable_reactions` - выключить реакции
- `/clear_history` - очистить историю сообщений
- `/mute <минуты>` - замьютить на указанное время
- `/unmute` - снять мьют
- `/say <chat_id> <текст>` - отправить сообщение в другой чат

### Только для владельца (Owner)
- `/add_admin <user_id>` - добавить администратора
- `/remove_admin <user_id>` - удалить администратора
- `/list_admins` - список всех администраторов
- `/set_owner <user_id>` - передать права владельца

## Настройка первого владельца

При первом запуске бота владелец устанавливается из переменной окружения `OWNER_ID` в файле `.env`:

```env
OWNER_ID=your_telegram_user_id_here
```

Узнать свой Telegram User ID можно через бота [@userinfobot](https://t.me/userinfobot).

## Управление ролями

### Добавление администратора
```
/add_admin <user_id>
```

### Удаление администратора
```
/remove_admin <user_id>
```

### Просмотр списка администраторов
```
/list_admins
```

### Передача прав владельца
```
/set_owner <user_id>
```
**Внимание:** После передачи прав текущий владелец становится администратором.

## Технические детали

- Роли хранятся в таблице `users` в базе данных
- Пользователи автоматически создаются при первом использовании команды
- Роли проверяются при каждом вызове команды
- По умолчанию все пользователи имеют роль `user`

## Безопасность

- Только владелец может управлять администраторами
- Владелец не может удалить сам себя из администраторов
- При передаче прав владельца старый владелец автоматически становится администратором
- Все команды проверяют права доступа перед выполнением
